## Context

All analytics data is available in `PREDICT_MAINT_DB.ANALYTICS`: 30 assets across 3 plants with health summary, OEE (avg 0.794), and maintenance costs (INR 953K total). The dashboard will run locally using `streamlit run` with a Snowpark session connecting to Snowflake. Alerts will be created as Snowflake `ALERT` objects that check for threshold breaches periodically.

## Implementation Steps

### Step 1: Create Streamlit dashboard (`streamlit_app.py`)

Single-file app with 4 sidebar pages:

**Page 1 — Asset Health Overview**
- KPI cards: total assets, assets in ALERT/ALARM, avg hours since maintenance
- Color-coded asset health table (NORMAL=green, ALERT=yellow, ALARM=red)
- Bar chart: vibration/temp baseline deviation by asset
- Filter by plant and asset type

**Page 2 — OEE Dashboard**
- KPI cards: avg OEE, availability, performance, quality
- Line chart: daily OEE trend (averaged across assets) over time
- OEE by plant bar chart
- Filter by plant, asset type, date range

**Page 3 — Maintenance Costs**
- KPI cards: total cost, corrective vs preventive split, avg MTBF
- Bar chart: cost by plant, cost by asset (top 10)
- Table: assets ranked by corrective WO count and total cost

**Page 4 — Sensor Deep Dive**
- Asset selector dropdown
- Time-series chart: vibration, temperature, current for selected asset (last 7 days)
- Rolling average overlay
- Threshold lines (alert/alarm) from ASSETS table

### Step 2: Create Snowflake Alerts (`sql/phase5_alerts.sql`)

Three alerts checking every 30 minutes:

1. **`PDM_VIB_ALARM_ALERT`** — fires when any asset has `VIB_STATUS = 'ALARM'` in latest reading
2. **`PDM_TEMP_ALARM_ALERT`** — fires when any asset has `TEMP_STATUS = 'ALARM'`
3. **`PDM_MULTIPLE_BREACH_ALERT`** — fires when any asset has `VIB_BREACH_COUNT_24H >= 10` (sustained degradation)

Alerts log to a `PREDICT_MAINT_DB.ANALYTICS.ALERT_LOG` table for audit.
