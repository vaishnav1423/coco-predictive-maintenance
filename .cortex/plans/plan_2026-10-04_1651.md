## Context

**Data characteristics:**
- 172,800 sensor readings with 36 engineered features in `ASSET_SENSOR_STATS`
- 39 historical failures with known degradation start + failure timestamps (from ground truth)
- 5 currently-degrading assets the model must detect: AST-024, AST-013, AST-027, AST-015, AST-011
- 6 false-alarm assets the model must NOT flag: AST-009, AST-021, AST-005, AST-028, AST-026, AST-022
- Anomaly rate is ~1.6% — highly imbalanced dataset
- No ML packages installed yet (only pandas in venv)

**Model approach — Binary Classification with ground-truth labels:**

Use the ground truth failure events to create labels: readings within the degradation window before each failure are labeled `1` (pre-failure), all others `0` (normal). Train a **Random Forest classifier** — it handles class imbalance well with `class_weight='balanced'`, needs no feature scaling, and provides feature importance out of the box. This is more practical than unsupervised anomaly detection since we have labeled failure events.

**Evaluation strategy:**
- Train on historical failures (39 events), test on the hidden validation set
- The 5 degrading-now assets should produce high anomaly scores at their latest readings
- The 6 false-alarm assets should NOT be flagged
- Metrics: precision, recall, F1, and a specific degrading-asset detection check
